# AI 对话与上下文锚点

锚点是 AI 抓住的阅读上下文。它描述「这段原文来自哪本书、哪一页」，随对话保存，帮助 AI 继续回答。高亮是用户保存到 PDF 上的标注，具有页内坐标，需要用户主动操作。

## 数据边界

| 对象 | 内容 | 存储与生命周期 | 读取方 |
| --- | --- | --- | --- |
| 起始上下文 `ConversationContext` | 用户选区、已有高亮引用，或整本书；语音提问包含当前页文本 | 会话的 `contextJson` 与 `sourceJson` | AI 起始上下文、用户保存引用/笔记 |
| 对话锚点 `ConversationAnchor` | ID、文档指纹、页码、原文、选词所在句与邻近语境、来源、创建时间 | `conversations.sourceJson.contextAnchors`；仅随用户明确删除会话 | 当前与后续 AI 回答、对话面板 |
| PDF 高亮 `Anchor` | 原文、页码、页内坐标、逐行矩形 | `anchors` 表；由用户主动保存 | PDF 覆盖层、标注索引、笔记 |
| 笔记 `Note` | 正文及关联高亮 ID | `notes` 表；由用户保存或确认 AI 建议 | 笔记面板 |

现有 `Anchor`、`anchor:save`、`saved-anchor` 等名称为高亮链路的历史命名。AI 上下文使用单独的 `ConversationAnchor` 类型，不向高亮表写入数据，也不需要解析 PDF 文本层的几何坐标。

## 从提问到回答

1. 点击「问 AI」继续当前讨论；没有当前讨论时恢复本书最近一次聊天，或创建阅读会话。点击高亮查看笔记不会切换聊天。
2. 每次发送优先提供选中文字，没有选区时提供当前页文本。选区加入当前会话的上下文锚点，不另开会话。「解释一下」直接发送解释请求，「询问 AI」打开输入框供用户自由提问。
3. 按住 Y 也延续当前聊天，使用按下时的选区或页码作为本次语音上下文。转写的已提交片段与最后片段合并后发送；当前页语音回合不提供书内搜索和跳页工具，后续文字回合恢复这些工具。
4. `conversation:send` 调用主进程的 `sendConversationMessage`。每轮创建 Agent 时，提供本次 `readingContext`、起始原文、已捕获锚点及历史消息。选区优先；当前页作为补充参考，不应使简短追问突然换话题。模型看到的页码为 1-based，存储与 PDF 渲染使用 0-based 页索引。
5. 需要书内检索时，AI 先调用 `ensure_book_index`，索引就绪后调用 `search_book`。本轮搜索结果保留为主进程可核对的原文来源。
6. AI 通过 `create_auto_anchor` 抓取支持回答的原文。主进程验证会话归属，并确认原文与页码能匹配本次阅读内容、起始来源、已捕获锚点或本轮搜索结果。不能用任意生成的句子创建锚点。
7. 相同页码和归一化原文复用同一个锚点。新锚点写入会话的 `sourceJson`，通过 `context_anchor` 事件更新「参考原文」。每次引用也更新 `activeContextAnchorId`，即使引用的是已有锚点。
8. AI 流式回答结束后，前端用 `conversation:resume` 按准确的会话 ID 读取完整消息与锚点。下一轮 Agent 将继续收到这些锚点。提示词要求仅在用户明确要求跳页时调用 `navigate_to_page`，平时由用户点击参考原文查看。

选区锚点与新增搜索锚点可以同时存在。新增锚点不会覆盖最初的选区，也不会改变会话与用户高亮的绑定关系。

## 阅读交互

- 默认连续讨论；「新话题」创建新的讨论并保留旧记录。「历史」按首个问题显示讨论标题。
- 输入框支持 Enter 发送、Shift+Enter 换行及中文输入法组合。回答过程中可以准备下一条问题。
- 工具结果保留在模型历史中，界面只显示用户问题、AI 回答和简短处理状态。参考原文默认折叠，用户无需管理锚点。
- 新回答在用户仍处于消息底部时自动滚动；向上查看旧内容时停止跟随，避免打断阅读。

## 恢复与删除

- 所有发出过问题的会话类型都进入本书历史，无自动删除数量上限。空白新话题只保留在内存，重复点击复用草稿；首个问题发送时才持久化。旧版本遗留的空会话不在历史中显示。
- 重开历史对话通过「会话 ID + 文档指纹」恢复，避免根据原文或高亮重新创建会话。恢复时重新绑定当前窗口的事件接收器。
- 旧数据没有 `contextAnchors` 时，从已保存的选区/高亮原文恢复起始锚点；无需新增数据库列或迁移已有高亮。
- 只有用户明确删除会话时，才删除其消息与上下文锚点；已保存的高亮和笔记独立保留。内存缓存目标为每书 10 条，闲置会话清理只移除缓存，正在回答或有待确认建议的会话保留。历史列表从持久化记录与活动会话合并，按 ID 随时恢复未缓存的记录。
- 删除高亮会删除其关联笔记，但保留 AI 对话。旧 `saved-anchor` 会话转为文档会话，保留原文、消息及上下文锚点，包含尚未加载到内存的会话。

- `lastUsedAt` 只在发送问题时更新；查看历史、工具调用、保存笔记不会改动排序。消息 ID 由会话 ID 与消息位置确定，恢复不会重新生成随机 ID，也不会截断长回答。
- 发送前保存用户问题，消息完成时保存，流式内容最多每秒检查点保存一次；停止生成、失败、关窗和退出时再次保存。已收到的部分回答标记为未完成；明确删除先停用会话再中断，防止后台写入复活已删除的记录。
- 快照携带实际 `status` 和单独的 `streamingText`，恢复正在生成的会话不会重复显示流式内容。切换历史或书籍通过请求序号丢弃过时响应；每条会话保留自己的未发送草稿。删除当前对话后恢复下一条历史，历史为空时回到提问入口。历史列表只在状态变化或操作完成后刷新，不逐 token 查询数据库。

## 选词语境

- 选区产生时读取实际 DOM Range，在 PDF 文本层定位该次选中内容，同时捕获 `selectedSentence` 和 `surroundingText`。同一页的同一个词出现在不同句子中时，优先使用实际选中的所在句，不取页面上第一次匹配的位置。
- 提问时保留 `quote` 为用户选中的词或短语，另携带所在句及邻近句。若未保留 DOM 选区上下文，则从该页 PDF 文本补充。无需全书索引或额外授权。
- 主进程将句子上下文存入会话阅读上下文和选区锚点，模型第一轮与后续追问均可读取；AI 还可将已提供的准确句子捕获为上下文锚点。指令要求先给出符合原句的解释/译法，无需用户再提供句子、学科主题或命令 AI 查看原文。

## 用户主动保存

「添加高亮」、保存引用、保存笔记，以及确认 AI 笔记建议，继续走既有高亮/笔记接口。AI 自动抓取上下文不会调用这些接口。

最新回答的「存为笔记」与可编辑的 AI 摘要使用 `conversation:save-note`。默认附在 AI 最近引用的锚点处；前端解析准确的 PDF 文本 Range 和逐行矩形，主进程确认它与会话原文匹配。已存在同页同文的高亮时复用，否则在用户主动保存时创建。保存笔记保留当前讨论，不另开对话；整页输入不会直接变成整页高亮。

选区会话保存为引用时，原始选区仍提供几何坐标。会话升级为 `saved-anchor` 并保留已有消息和上下文锚点；其他自动抓取的锚点不会一起转换成高亮。

## 回归验证

`npm test` 使用真实 AI 服务代码、模拟 Agent 和内存存储验证：上下文捕获、连续换页/换选区提问、语音与文字回合、去重、最近引用来源、原文匹配、窗口归属、重启恢复、旧数据兼容、超过 50 条会话的保留、空白新话题、查看历史不改排序、完整长回复、失败与中断保存、删除不复活、删除高亮保留历史、选词所在句、删除及用户主动保存；另验证 PDF 跨节点原文定位。

`npm run build` 后可运行 `npm run test:ui`，无显示器的 Linux 使用 `xvfb-run -a npm run test:ui`。它用真实生产版 Electron 界面、测试 PDF 和模拟桥接验证一键解释、回车发送、连续追问、准确定位笔记、完整语音转写、恢复聊天与新话题。测试不访问真实模型 API 或用户数据库，不覆盖真实模型是否会在某个问题下选择调用工具。
